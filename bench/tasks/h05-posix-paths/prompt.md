The path helpers in `src/paths.ts` are used by our browser build, where `node:path` doesn't exist. They were written to "work like Node's `path.posix`", but users keep hitting differences: `normalize('../a')` drops the `..`, `normalize('a/..')` returns an empty string, `relative('/a', '/a')` is fine but some sibling and root cases come out wrong, and `dirname`/`basename` mishandle trailing slashes.

Make `normalize`, `join`, `relative`, `dirname` and `basename` return exactly what Node's `path.posix.normalize`, `path.posix.join`, `path.posix.relative`, `path.posix.dirname` and `path.posix.basename` (without the extension argument) return, for any string input. `relative` is only ever called with two absolute paths. `src/` must not import `node:path` or any package. Keep the existing tests passing and add tests for the edge cases you fix.
